## 2. What was finished this session

### v1.2 — amplified recording save (`baa6a7f`)

Jeff's report was "it records but doesn't save." Two stacked defects, both found
with an instrumented APK rather than by reasoning:

1. **`stop()` hung forever.** `package:record`'s PCM stream does not close when
   the recorder stops, so `await subscription.asFuture()` never returned. The
   device trace stopped dead between `before drain` and `drained` and stayed
   there 36+ seconds. No error, nothing logged. Fixed with
   `drainPcmSubscription`, which waits on the stream's done event with a 750ms
   bound — that timeout is the NORMAL path, not a safety net.
2. **SAF renamed the file.** The Kotlin layer declared `audio/ogg` for all
   audio; AOSP appends a MIME-derived extension when name and MIME disagree,
   publishing `<id>.wav.oga` at 0 bytes. Fixed with `audioMimeForSuffix`.

The zero-length WAV header was a *symptom* of #1, not a third bug — the header
patch sits after the drain and was never reached.

**Verified end-to-end on the tablet:** 7.8s at 4.0× gain → 250,924 bytes, exact
RIFF/data lengths, peak 16760, plays back in-app, transcribed over Tailscale via
large-v3.

Two near-misses worth remembering: `FileMode.write` would have **truncated
recordings to 8 bytes** (probe disproved it before shipping), and the first
drain test passed only because its own timeout fired — a hang wearing a hat.

### Checkbox Enter (`edc6fa9`)

Jeff: *"when you are in the text area of a checkbox item, you can hit enter and
it will go into another checkbox list item, not expand the box."*

The field is `maxLines: null`, so Enter inserted a newline. Enter is now
intercepted above the field (`_BackspaceDeletes`, the same seam the empty-line
backspace already used) and calls `_splitCheckboxBlock`, which inserts a new
checkbox **directly after its source** and moves the caret into it.

Three decisions made without asking, all covered by tests:
- Enter on an **already-empty** item ends the list rather than adding another
  blank one.
- Plain text blocks pass no `onSplitLine` and keep taking newlines.
- The new block is unplaced (null x/y) so it flows beneath its source instead of
  landing on top of it.

Sabotage-proven both ways. **Not yet verified on hardware** — see §4.

### 3.2 Device sync through the Docker container

**Jeff asked whether this is possible through the Docker container. It is.**
The container *is* the server — `tangent-server`, host port 8765, reachable on
Tailscale. No third-party cloud involved. Findings:

**Already exists:**
- Server: full dumps CRUD, plus audio upload/download
  (`POST/GET /v1/dumps/{id}/audio`), jobs with SSE streaming, models, setup,
  server info. Baseline 125 passed / 1 skipped.
- Client: a `SyncEngine` with `syncNow()` — but it is **one-way upload only**
  (opt-in backup). No pull, no device identity, no conflict handling.
- A thorough design doc: **`docs/design/multi-device-sync.md`**, status
  "proposed", currently **untracked**. It already settles the model:
  server-assigned monotonic `change_seq` as a checkpoint, per-entity merge, with
  last-write-wins on `updatedAt` explicitly rejected on data-loss grounds (whole
  notebook granularity would silently destroy a page of ink). Read it before
  designing anything — the decisions are made.

**The actual gap:** the server has **no notebooks or text-notes tables or
endpoints** (`server/app/models.py` defines only setup/dump/job/server-info
shapes). Sync of the things Jeff wants synced does not have a server side yet.

**Scope per the design doc:** syncs notebooks (ink + typed blocks + card refs),
text notes, dump metadata, transcripts. **Does not sync audio** — audio stays on
the recording device and transfers only on explicit request. This matches Jeff's
earlier instruction: *"I just want the files stored locally on the device, not
backed up to the cloud. I only need it to transcribe over tailscale when I am
connected to mobile."*

**Build it for everyone, not this tablet.** Jeff: *"keep in mind that the sync
is to be built for everybody, not a dedicated samsung tablet. So be sure to

Suggested order: server schema + endpoints for notebooks/text-notes with

### 3.3 Content-aware insert position

Jeff: *"there needs to be content recognition of some sort where when you are
typing or entering in pen input where when you select Insert -> textblock or
checkbox it recognizes where you last entered in information and then enters in
the next text/checkbox below where you are currently entering in the
information."*

Today `_addTextBlock()` (line ~199) and `_addCheckboxBlock()` (line ~211) both
**append to the end of `_blocks`** with null x/y, so a new block lands at the
bottom of the page regardless of where you were working.

**The pattern already exists**: `_splitCheckboxBlock` (added this session)
inserts after a given index via
`..._blocks.take(index + 1)` / `..._blocks.skip(index + 1)`. Reuse it.

Two halves, and the second is genuinely harder:
- **Typed input:** track the last focused/edited block id (focus nodes now exist
  in `_focusNodes`, added this session) and insert after that index. Fall back
  to appending when nothing has been touched yet.
- **Pen input:** ink strokes are **not blocks** — they live in a separate
  `_strokes` list on the ink canvas. "Where you last wrote" has to be derived
  from the last stroke's bounding box, then converted into an insertion position
  among the flow blocks. This needs a decision from Jeff about what "below"
  means when ink and typed blocks interleave. **Ask rather than guess.**

Relevant: `client/lib/screens/notebook/notebook_editor_screen.dart`,
`client/lib/widgets/notebook_ink_canvas.dart`,
`client/test/widget/notebook_editor_screen_test.dart` (43 tests, the harness to

## 6. Things that will bite you

- **CRLF.** Sources are CRLF. An LF search string never matches and the miss
  reads as a passed sabotage. Use the `patch` tool, not string replacement in
  `execute_code` — that failed twice this session and left a sabotage in place.
- **`--plain-name` filters by test title.** A sabotage that "passed" this
  session had simply not run the relevant test. Check which tests actually
  executed before recording a result.
- **`search_files` returned empty for real paths** inside `execute_code` several
  times. Cross-check with `grep` in `terminal` before believing an absence.
- **Never run two `flutter test` suites at once** — timing-sensitive tests fail
  in bulk under contention.
- `_addTextBlock` and `_addCheckboxBlock` contain a `..._blocks,` spread that is
  textually identical to the one in `_splitCheckboxBlock`. A `patch` on that
  fragment matches multiple sites — include surrounding context.
- Credentials: `server/.env` is gitignored and holds the API token. The server
  stores only a SHA-256 and `/v1/setup` refuses to reissue. **Never** print the
  value, a fragment, or the hash into chat, commits, or docs.

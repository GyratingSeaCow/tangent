# Morning Brief — AI daily summary on the morning review screen (v1.41)

Status: SPEC'D, queued behind v1.40 (ask actions + full-screen morning review).
Decisions below are Jeff's, final, 2026-10-01.

## What

A Claude-style daily brief at the top of the full-screen morning review:
a short narrative paragraph + a few bullet highlights, generated by the
server's existing local summarizer (Qwen3-4B-Instruct-2507 Q4_K_M via
llama-cpp-python in the tangent-server container). No new model, no new
runtime — this rides the AI-summaries environment exactly as installed.

## Decisions (final)

1. **Pre-generated server-side around dawn (~05:00 server-local)** so the
   screen opens instant. CPU inference (~30–60 s for a day's content) is
   the expected runtime on this host (Blackwell wheel gap → CPU landing,
   see ai-summaries reference); a scheduled job absorbs it invisibly.
2. **Gate = AI summaries installed + enabled.** Not installed → the brief
   section is HIDDEN entirely; the rest of the morning review stands
   alone. No teaser line.
3. **Style: narrative paragraph + a few bullet highlights.** Conversational,
   not a wall of bullets. No invention — same no-invention discipline the
   meeting summarizer passed adversarial probes on; empty day → honest
   short line, never fabricated content.
4. **Scope: v1.41, its own branch, after v1.40 merges.** Server + client
   in one arc.

## Shape (for the implementer)

### Server
- New template id `morning_brief` in `summary_templates.py`
  (TEMPLATE_DEFINITIONS). Input is an AGGREGATE, not one transcript:
  yesterday's dumps (title + summary if present, else transcript head),
  today's due to-dos, pinned items. Keep the drift-guard test for the
  meeting preset byte-for-byte.
- Scheduled generation ~05:00 server-local; idempotent per date; result
  cached per-day (suggest `morning_briefs` table or app_settings-adjacent
  row: date, brief_md, model, generated_at). Regenerate only on explicit
  request.
- `GET /v1/morning-brief?date=` → 200 {brief_md, generated_at, model} |
  404 not generated | 409 summarizer not installed (detail strings are
  load-bearing client-side — follow the existing 409 classifier pattern
  in summaries_client.dart).
- Trigger failure must never break anything else (try/except like
  maybe_enqueue_auto). Worker reuse: same summarizer_worker child, same
  child_env() for any new spawn path.

### Client
- Brief section renders at the TOP of morning_review_screen.dart as
  read-only markdown (`flutter_markdown_plus`, pinned ^1.0.3 — do NOT
  bump, path-dep conflict).
- Hidden when: 409/not-installed, 404/not-generated-yet, or empty.
  Never a spinner blocking the screen; the brief is additive.
- Pull on screen open (cheap GET, served from cache); no client poller.

### Verification
- Fakes close the API contract; the REAL model output quality check is a
  live-E2E item on the container (ledger it explicitly, per the
  ai-summaries arc lesson).
- Probe an empty-capture day and a heavy day; adversarial no-invention
  probe on the brief prompt before Jeff sees it.

## 4. THE ONE OPEN DEFECT — Fold bulk/single download does nothing

### Symptom

On the Fold only: the ⋮ menu shows **"Download audio — Choose a storage folder first" (greyed, `enabled=false`)**. Bulk download from the selection toolbar produces no snackbar, no server request, no files. Identical APK works perfectly on the tablet.

### What the greyed state means in code

`dumps_list_screen.dart:538`
```dart
final bool canDownload =
    downloadable && ref.read(syncedAudioDownloaderProvider) != null;
```
So **`syncedAudioDownloaderProvider` is returning null** on the Fold.

`dumps_providers.dart:23-41`
```dart
final AsyncValue<DefaultFolderState> folder = ref.watch(defaultFolderProvider);
final StorageLocation? location = folder.valueOrNull?.location;
if (location == null || folder.valueOrNull?.available != true) return null;
```

### Ruled OUT by evidence (don't redo these)

| Hypothesis | Evidence it's not the cause |
|---|---|
| Network / server unreachable | `nc` RC=0; `sync/pull 200` from the same device |
| Missing or disabled buttons | `uiautomator` confirms toolbar buttons enabled, coords verified |
| No storage location configured | `storage_locations` row exists |
| Stored capability differs from tablet | **Byte-identical** `directory_json` on both devices (same `treeUri`, `documentId`, authority) |
| No OS permission grant | `dumpsys activity permissions` shows the Fold **holds** `content://com.android.externalstorage.documents/tree/primary%3ADocuments%2FTangent`, `persisted=0x3` (read+write) — same as the tablet |
| Bad `default_location_id` | Valid UUID present, matches the `storage_locations` row |
| Bulk-specific bug | **Single-row ⋮ download is equally dead** — narrower repro |
| Wi-Fi-only refusal | Would show the Wi-Fi snackbar; also identical setting on both devices |

### Two real discoveries this session

1. **The folder grant does NOT survive an `adb install -r`.** After granting (Settings → Change folder → Documents/Tangent → USE THIS FOLDER → **ALLOW**) the entry went **enabled**. After the next reinstall it was greyed again. Every earlier "the Fold is broken" test ran on a fresh install, so the Fold never had a live grant at test time. **Re-grant after every install on the Fold.**
2. **The grant also didn't survive a plain app restart** in one trial (granted → force-stop → relaunch → greyed), even though the OS still held `persisted=0x3`. That points at app-side state, not the OS.

### Leading hypothesis for the next session

`storage_catalog.dart:217-225`
```dart
Stream<DefaultFolderState> watchDefault() async* {
  await _ready();          // <-- suspect
  await for (final _ in _db.customSelect(...).watch()) {
    yield await _present(await _state());
  }
}
```

`watchDefault()` awaits **`_ready()`** before its first yield. `_ready()` (line 57) does `_backend.unsettledUses()` → `_mutations.restoreFences()` → `catalogAdmission(...)`.

**If `_ready()` hangs or throws on the Fold, the stream never emits**, `folder.valueOrNull` stays null, the provider returns null, the entry greys — and **nothing logs**, because the inspect-failure log I added lives *after* that await. This matches every observed symptom, including the silence.

Supporting evidence: the inspect-failure `debugPrint` **never fired** on the Fold, so execution isn't reaching `_present`'s else-branch.

Why the Fold might differ: it has 75 dumps with unsettled state / fence records from all the interrupted runs; the tablet's catalog is clean.

### Exact next steps

1. Add `debugPrint` at the **top of `_ready()`**, after `unsettledUses()`, after `restoreFences()`, and after `catalogAdmission` — find which one never returns.
2. Also log the first `yield` in `watchDefault()` and whether `defaultFolderProvider` ever leaves `AsyncLoading`.
3. Rebuild, install, **re-grant the folder on the Fold**, then read `adb -s RFGL82VCV6V logcat -d | grep tangent`.
4. Check `unsettledUses()` against the Fold's staging dir — a large or corrupt unsettled inventory is the prime suspect for a hang.
5. If `_ready()` is the culprit: it must not be able to block the folder stream forever — bound it, or emit an initial state before awaiting it.

### Logging gotcha (cost me several cycles)

**`developer.log()` does NOT appear in logcat on these devices.** Use **`debugPrint`** — it surfaces as `I/flutter`. The current uncommitted diagnostics already use `debugPrint`.

- **Device proof is mandatory** — screenshots plus persisted DB/file evidence. Unit tests are *not* hardware acceptance.
- **Never** uninstall, `pm clear` the app, or delete staging. Never `pm clear` a launcher. Real user audio is on these devices.

- Read UI coordinates **fresh** from live screenshots or `uiautomator dump` — never reuse old ones.
- TDD: RED test before production code; sabotage to prove edits are load-bearing.
- Never run two `flutter test` concurrently. Terminal timeout **≤ 600s**.
- Sources are **CRLF** — prefer the `patch` tool. Generated patches must be raw bytes (`git diff --binary` + `'wb'`).
- Don't infer build success from `tail` — parse the Gradle test XML.
- On-device DB pull **must** use `adb exec-out run-as ... cat`.
- Complex backslashed one-liners fail under MSYS — write `.py` files. MSYS mangles quoted paths with spaces in `adb shell ls` — use `subprocess` with arg lists.
- Fold has multiple displays: verify the live panel by screenshot **file size** (dark panel = few KB, live = hundreds of KB).
- Never overload the row long-press (bulk-delete entry point, 28 tests protect it).
- Fail loud, never silent — a tapped control must always report what happened.

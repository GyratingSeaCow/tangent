# Text Note Implementation Plan (v2 — post-audit)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a third capture mode — Text Note — that saves typed notes into the existing Dumps collection with full list/search/selection/deletion/sync/durable-folder support.

**Architecture (REVISED after pre-dispatch audit):** A text note is a `dumps` row with `mode='text_note'`, body in `transcript`, `transcriptionStatus='not_applicable'`, `durationSeconds=0`. **No schema migration — schema stays 5.** The note's published `.md` file occupies the existing primary-content (audio) component slot: `audioPath` holds the `.md` locator, `audioSizeBytes` its byte length, so every existing bind/commit/cleanup/journal invariant (`row.audioPath == binding.audio.value`, `audioSizeBytes == stopped.sizeBytes`) holds unchanged. Component filenames become mode-aware (`<id>.opus` audio modes / `<id>.md` text_note) across codec, capture IO, and both storage backends. UI/sync branch on `mode`, never on audioPath.

**Tech Stack:** Flutter/Dart (Drift 2.20.2, Riverpod), FastAPI/pydantic server, existing storage catalog/backend.

**Spec:** `docs/superpowers/specs/2026-09-17-text-note-design.md` (revised — data-model section is authoritative). This plan supersedes v1; v1's schema-6 migration is DELETED, not deferred.
